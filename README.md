# CoruñaWTF Website

Website of **CoruñaWTF**, a local community in A Coruña focused on web development and design.

The site is plain HTML and CSS generated by a dependency-free Node script (`scripts/build.mjs`):
templates in `scripts/lib/render.mjs`, styles in `site/static/styles/site.css`, texts in `data/content.json`
and legal pages in `site/legal/`. **Events come from the
[Luma calendar](https://luma.com/corunawtf)**: publish an event there and the next build picks it up
for both the web and the [Open Tech Events (OTE)](https://opentechevents.org/) feed.

## How it works

```
Luma calendar (iCal feed) ──┐
data/history.json (≤ 2026) ─┼─> scripts/build.mjs ──> dist/index.html
data/overrides.json ────────┘                         dist/feed.json   (OTE 0.6.0)
```

- `scripts/build.mjs` downloads the public iCal feed of the calendar, converts times to Europe/Madrid,
  merges them with the older events in `data/history.json` and writes `dist/`.
- The GitHub Action in `.github/workflows/site.yml` builds, tests, **validates the feed against the
  official OTE schema** and deploys to GitHub Pages on the 1st of every month and on demand.
  If Luma cannot be reached the build fails, so the live site is never replaced by one without events.
- The feed is published at `/feed.json` and advertised with `<link rel="alternate" type="application/ote+json">`.

## Adding an event

Create it in Luma. That's it. The site picks it up on the 1st of the month, or right away if you run
the workflow by hand (Actions → "Build and deploy site" → Run workflow). Changes to the code or to
`data/` are only published the next time the workflow runs.

Luma's iCal feed carries no speakers and no description, so you can add them in `data/overrides.json`,
keyed by the event slug (`luma.com/<slug>`):

```json
{
  "3gmwi392": {
    "subtitle": "Optional subtitle",
    "description": "Optional text. If omitted, the event page's short description is used.",
    "speakers": [{ "id": "andrea" }, { "name": "Guest without a profile" }],
    "slides": "https://…"
  }
}
```

Overrides also accept `"slides": "https://…"`. Events before Luma live in `data/history.json`;
each one can have `url` (its Eventbrite page) and `slides`, shown as links on its card.

A speaker with an `id` from `data/speakers.json` gets a photo and profile on the web; one with only a
`name` is shown as text.

### Events published outside Luma

Add them to `data/events.json` (date and time in Europe/Madrid). They behave like Luma events:
they can be the "next event" in the hero and the header button, and they go into the OTE feed.

```json
[{
  "slug": "merge-christmas-2026",
  "title": "Merge Christmas",
  "subtitle": "Optional",
  "description": "Optional",
  "date": "2026-12-03",
  "time": "19:00",
  "url": "https://merge-christmas.pages.dev/",
  "location": { "venue": "Bellini Rooftop", "address": { "street": "…", "postalCode": "…", "locality": "A Coruña", "country": "ES" } }
}]
```

## Development

Requires Node 20+.

```bash
npm install          # only needed for `npm run validate`
npm test             # unit tests
npm run build        # writes dist/
npm start            # build for http://localhost:3000 and serve it
npm run validate     # checks dist/feed.json against the OTE schema
```

Useful variables: `LUMA_ICS_FILE=path.ics` (use a local file instead of downloading),
`SKIP_ENRICH=1` (don't read event pages), `BUILD_NOW=2026-11-01T10:00:00Z` (pretend it's another date), `BASE_PATH=` (serve from `/`, handy for local preview),
`SITE_ORIGIN`.

## Configuration

`data/site.json`: site name, URL (`origin` + `base`), Luma calendar, data license of the feed
(`license`) and `coversFrom`, the date from which the feed claims to list every event.
